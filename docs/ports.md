# Сервер AmneziaWG на диапазоне портов

> Раздел документации [awg-proxy](../README.md): контейнер RouterOS, который подключает MikroTik к серверам AmneziaWG. Остальные разделы: [FAQ](faq.md) · [установка](install.md) · [обновление](update.md) · [переменные](env.md) · [AWG 3.x и IPv6](protocol.md) · [маршрутизация и MTU](routing.md) · [серверный режим](server-mode.md) · [неполадки](troubleshooting.md).

Сервер AmneziaWG слушает один UDP-порт. Если именно этот порт перестаёт проходить — у провайдера, в сети отеля, на мобильном интернете, — туннель встаёт, хотя сам сервер жив. Если же сервер принимает клиентов сразу на тысячах портов, awg-proxy:

- берёт **случайный порт из диапазона при каждом подключении**, так что разные роутеры и разные сессии не сидят на одном и том же порту;
- **уходит с порта, который не отвечает, примерно через 15 секунд**, а не ждёт минуту `AWG_TIMEOUT`;
- время от времени **меняет порт на ходу, незаметно для пользователей** (`AWG_PORT_ROTATE`, см. [переменные](env.md)).

Сервер при этом не меняется: ядро перенаправляет все порты диапазона на настоящий порт AmneziaWG. Клиенты, которые о диапазоне не знают (телефоны, ноутбуки с приложением AmneziaVPN), работают как раньше.

## Быстро: скрипт одной командой

На сервере (Ubuntu, Debian, CentOS/Alma/Rocky и т. п.), под пользователем с `sudo`:

```bash
curl -fsSL https://raw.githubusercontent.com/timbrs/amneziawg-mikrotik-c/main/scripts/awg-ports.sh | sudo bash
```

Скрипт:

1. **Находит сервер сам**: интерфейсы `awg`/`wg` на хосте (модуль ядра amneziawg, amneziawg-go, WireGuard) или Docker-контейнер AmneziaVPN (`amnezia-awg`) с его UDP-портом. Если не нашёл — спросит порт.
2. **Спрашивает, сколько портов взять** (по умолчанию 10 000).
3. **Подбирает свободный диапазон** между 10000 и началом эфемерных портов ядра (обычно 32767), со случайным началом — чтобы у разных серверов диапазоны не совпадали. Порты, которые кто-то слушает, порты чужих правил NAT и опубликованные порты Docker обходит: диапазон тогда будет из нескольких кусков.
4. **Показывает диапазон и спрашивает разрешения**, потом ставит правила iptables в отдельную цепочку `AWG_PORTS`.
5. **Делает так, чтобы это пережило перезагрузку**: служба systemd `awg-ports` и проверка раз в минуту (`awg-ports-check.timer`). Проверка возвращает правила, если их снёс перезапуск файрвола или Docker, и подхватывает новый адрес контейнера.
6. **Печатает, что вставить в конфигуратор**, например:

   ```
   20113-30112
   ```

Повторный запуск (`sudo awg-ports` или та же команда с `curl`) ничего не ломает: он показывает текущие настройки, сколько подключений пришло через диапазон, и предлагает **r** — перенастроить, **d** — удалить, Enter — выйти.

Хотите сначала прочитать скрипт — скачайте его отдельно:

```bash
curl -fsSLo awg-ports.sh https://raw.githubusercontent.com/timbrs/amneziawg-mikrotik-c/main/scripts/awg-ports.sh
less awg-ports.sh
sudo bash awg-ports.sh
```

Без вопросов, для своих скриптов:

```bash
sudo awg-ports --setup --port 51820 --count 10000 --yes          # сервер на этом хосте, UDP 51820
sudo awg-ports --setup --container amnezia-awg --count 5000 --yes # сервер AmneziaVPN в Docker
sudo awg-ports --status                                          # что настроено и работает ли
sudo awg-ports --remove                                          # убрать всё
```

Все опции — `awg-ports --help`.

**Безопасность.** Перенаправляется только трафик, адресованный самому серверу (`-m addrtype --dst-type LOCAL`). Трафик VPN-клиентов к чужим серверам на тех же портах проходит мимо, как и раньше.

**Файрвол хостера.** Если у VPS есть свой файрвол в панели управления (security groups, «Сетевой экран»), откройте там UDP-диапазон, который выдал скрипт. Сам скрипт до него не дотянется.

## Как указать диапазон для MikroTik

Любой из трёх способов:

- **Конфигуратор.** Отметьте галочку **«Сервер принимает AmneziaWG на нескольких портах»** и вставьте диапазон, который выдал скрипт.
- **Строка в `.conf`.** Допишите перед `[Peer]`:

  ```
  # AllowedPorts = 20113-30112
  ```

  Конфигуратор сам найдёт её и поставит галочку. Такую строку пишут и некоторые боты, выдающие ключи.
- **Вручную** — в переменной контейнера `AWG_REMOTE`: `203.0.113.5:20113-30112`. Можно перечислять порты и диапазоны через запятую, до 32 кусков: `203.0.113.5:20113-24000,24002-30113`.

**Роутер уже настроен?** Сгенерируйте команды в конфигураторе заново, с галочкой, и выполните их: как сделать это без дублей — [FAQ](faq.md#конфигуратор-обновился-сносить-всё-и-ставить-заново).

Одного только диапазона на MikroTik мало: если сервер не принимает эти порты, прокси будет попадать в молчащие порты и переключаться. Сначала сервер, потом роутер.

## Хаб на MikroTik (серверный режим)

Если сервер — это MikroTik в режиме «Сервер (1:N хаб)», диапазон делает файрвол самого хаба: правило dst-nat отправляет все порты диапазона на один порт контейнера.

- **Новый хаб.** В конфигураторе заполните поле **«Ещё порты сервера»**, например `30000-30999`. Конфигуратор поставит на хаб dst-nat и правило forward на основной порт и диапазон, а клиентам пропишет их в `AWG_REMOTE`. Диапазон сохраняется в ссылке «добавить клиента», так что и следующие клиенты получат его сами.
- **Хаб уже стоит.** Добавьте диапазон к его двум правилам (`awg-server-1` — префикс вашей установки, `27015` — её порт) и к правилам IPv6, если они есть:

  ```routeros
  /ip/firewall/nat/set [find comment=awg-server-1-dstnat] dst-port=27015,30000-30999
  /ip/firewall/filter/set [find comment=awg-server-1-awg-in] dst-port=27015,30000-30999
  ```

  Затем на каждом клиенте — диапазон в `AWG_REMOTE` и перезапуск контейнера:

  ```routeros
  /container/envs/set [find list=awg-server-1-env key=AWG_REMOTE] value="203.0.113.5:27015,30000-30999"
  /container/stop [find interface=veth-awg-server-1]
  /container/start [find interface=veth-awg-server-1]
  ```

Выбирайте диапазон, на котором у хаба нет других пробросов портов: dst-nat заберёт весь диапазон себе. **На хабе нужен awg-proxy 1.4.4 или новее.** Пока новый порт не ответил, клиент шлёт каждый пакет на оба порта, и старый хаб уводил ответы обратно на старый порт — смена каждый раз откатывалась (связь не рвалась, но порт не менялся).

## Вручную, без скрипта

### Сервер на самом хосте (модуль ядра, amneziawg-go, WireGuard)

Пусть сервер слушает UDP 51820, а диапазон — 20000–29999:

```bash
iptables -t nat -N AWG_PORTS
iptables -t nat -A AWG_PORTS -p udp --dport 20000:29999 -j REDIRECT --to-ports 51820
iptables -t nat -I PREROUTING 1 -m addrtype --dst-type LOCAL -j AWG_PORTS
```

То же для IPv6 — те же команды с `ip6tables`. Сохранить на перезагрузку: `apt install iptables-persistent` и `netfilter-persistent save` (Debian/Ubuntu) или аналог в вашем дистрибутиве. На системах с nftables эти команды тоже работают: в современных Debian и Ubuntu `iptables` — это обёртка `iptables-nft`.

### Сервер AmneziaVPN в Docker

AmneziaVPN держит сервер в контейнере (`amnezia-awg`) и публикует его UDP-порт. `REDIRECT` здесь не годится: пакеты надо отправить прямо в контейнер.

```bash
CIP=$(docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' amnezia-awg)
iptables -t nat -N AWG_PORTS
iptables -t nat -A AWG_PORTS -p udp --dport 20000:29999 -j DNAT --to-destination $CIP:51820
iptables -t nat -I PREROUTING 1 -m addrtype --dst-type LOCAL -j AWG_PORTS
```

Здесь `51820` — порт сервера внутри контейнера (в `docker ps` — число справа от `->`). Адрес контейнера может смениться после его перезапуска — тогда правило придётся обновить. Скрипт делает это сам раз в минуту, поэтому для Docker лучше он.

## Проверка

- На сервере: `sudo awg-ports --status` — число подключений через диапазон растёт, когда роутер подключается.
- На MikroTik: в логе контейнера строка `connected to <адрес> port <порт>` — порт из диапазона, при каждом переподключении другой.
- Проверить конкретный порт можно и без роутера: `tcpdump -ni any udp port 20113` на сервере, а с клиента — подключиться с этим портом в `Endpoint`.

## Что ещё стоит знать

- **Cloudflare WARP** уже принимает WireGuard на портах 2408, 500, 1701 и 4500, и конфигуратор подставляет их сам. Меняться на ходу между ними нельзя: Cloudflare держит сессию на том порту, где она началась, поэтому прокси узнаёт WARP по ключу сервера и держится за порт, который ответил, а другой пробует, только если этот замолчал. Несколько адресов WARP -- в [FAQ](faq.md#можно-дать-прокси-несколько-адресов-warp).
- **Порты ниже 10000 и эфемерный диапазон ядра** (обычно от 32768) скрипт не берёт: первые нужны службам, вторые ядро раздаёт исходящим соединениям самого сервера.
- **IPv6.** Если у сервера есть публичный IPv6 и сервер AmneziaWG работает на самом хосте, скрипт ставит те же правила и в `ip6tables`. Для сервера в Docker — только IPv4.
- **Удаление**: `sudo awg-ports --remove` — правила, служба и настройки уходят, сервер снова слушает только свой порт. На роутере после этого уберите диапазон из `AWG_REMOTE`, иначе прокси будет попадать в молчащие порты.
